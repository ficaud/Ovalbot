# AGENTS.md — OvalBot

Development notes kept up to date by the agent as work progresses.

## Project

Ticket resale bot for Stade Rochelais home games + a simple website (2 pages).
Stack: Rust/Axum (backend) + SvelteKit (frontend) + SQLite. Hosted on a Raspberry Pi (arm64) via Docker Compose. The bot (Phase 4) will be integrated last.

## Structure

- `src/` : Rust backend — Axum server (`main.rs`) + CLI (`bin/create_admin.rs`).
  - `src/common/` : foundations (`error`, `models`, `time`, `db`).
  - `src/services/` : business + integrations, en sous-groupes — `accounts/` (`auth`, `waitlist`, `email`), `channels/` (`mailer`, `telegram`, `alerts`), `bot/` (`mod` = scan loop, `matching`, `resale`) + racine (`notifications`, `tickets`, `calendar`, `state`).
  - `src/routes/` : HTTP layer (Axum handlers), one file per resource (`admin`, `auth`, `calendar`, `notifications`, `telegram`, `tickets`).
- `migrations/` : SQL migrations (sqlx).
- `frontend/` : SvelteKit (Svelte 5, `adapter-static`).
- `doc/specs/` : specifications (`cdc.md`) + per-phase specs (`phase1.md`).
- `Dockerfile` + `docker-compose.yml` : deployment (arm64 image published on GHCR).

## Commands

- Server : `cargo run --bin ovalbot`
- Create admin : `cargo run --bin create_admin -- --email <email> --password <pwd>`
- Tests : `cargo test`
- Lint : `cargo fmt --check && cargo clippy --all-targets -- -D warnings`
- Frontend : `cd frontend && npm run dev` / `npm run build`
- Devcontainer : `./my-env/up.sh` / `./my-env/down.sh`

## Conventions

- Documentation: every function (pub and private) carries a rustdoc `///` comment — with `# Arguments` / `# Returns` / `# Errors` / `# Panics` sections when relevant — every struct/enum gets a doc line (fields where it clarifies), and every module opens with a `//!` header. Local variables stay uncommented unless non-obvious. Keep docs factual and short; comments stay in English.
- Unit tests are mandatory for every business function implemented.
- Code and comments are written in English.
- Section separators use plain `//` comments (never `///`, reserved for doc comments that attach to the next item).
- Test functions get a one-line `//` intent comment when their name alone doesn't tell the story.
- Axum 0.8 : path params use `{id}` (not `:id`).
- Cookies : `axum-extra` (feature `cookie`).
- Migrations : `sqlx::migrate!()` embedded at runtime + `sqlx-cli` (sqlite) in dev to create files.
- SQL : runtime-checked `query`/`query_as` for Phase 1.

### 2026-10-24 — Seats-alert email: columnless seat rows (Apple Mail regression fix)
- Symptom (user screenshot, Apple Mail iOS dark mode): the price column rendered **one character per line** ("3 8 - 5 0 €" stacked vertically), misaligned above its label row, with the row heights blown up. The 2026-10-24 "responsive" fix (`price cell width="1%" + nowrap`, label `width="99%"`) made it worse: Apple Mail honored the `1%` width but dropped the `nowrap` hint → the price column shrank to ~1 character and per-character wrapping won over the no-break constraint. Lesson: on mobile Apple Mail, `width` attributes are honored but wrap-discrimination is not — a two-column 99%/1% split with a nowrap-last-column contract can never hold.
- Fix (user-validated "no columns at all"): `seat_html_row` now emits **one full-width `<tr>` per seat, one `<td>`, zero columns** — bold ticket line `🎟️ {bloc} <span #FFD500>— {price} €</span>` (single text flow) + optional gray `<p>` position line ("Rang {row} · Siège {n}"). Nothing left for a client to narrow: too-long labels wrap at word boundaries, the price can never land in its own 1%-wide column. Guard asserted in tests: `!contains("width=\"")` + `!contains("nowrap")`.
- Doc comments rewritten (row-pair wording gone), including a hard rule in `seat_html_row`'s doc: **extension/redesign must not reintroduce multi-column tables here**. `tests/mailer.rs` transport assertions unaffected (they check the same strings in the new single-flow line). `defaults()` template untouched (it already wraps `{{seats_html}}` in a `width="100%"` presentation table).
- Preview rendered to `/tmp/seats_alert_preview.html` (fixture seats incl. the screenshot's "38-50" price) for an Apple Mail sign-off before sending any real alert.
- Verified: `cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`, `cargo doc --no-deps`, `cargo test --workspace --jobs 2` all green (18 suites: 44 lib incl. 2 reworked alerts tests, 7 mailer, 12 notifications, 45 routes, 17 tickets, 61 parser, 34 calendar).

### 2026-10-24 — Log timestamps in Paris time (`Europe/Paris`)
- Goal: user request — terminal logs carried the tracing default (`SystemTime`, UTC, `Z` suffix); they should read Paris time.
- `tracing-subscriber` 0.3.23 has **no `jiff` feature** (only `chrono`/`time` built-ins; checked docs.rs) → `chrono` route needs system tzdata (absent from the `debian:trixie-slim` runtime image) and `time` cannot resolve `Europe/Paris` → one new dep **`jiff` 0.2** (embedded tz database, DST handled in-Rust, zero system dependency) and a small custom timer.
- `src/main.rs`: `ParisTime(TimeZone)` implementing `FormatTime` over `format_paris(Timestamp, &TimeZone)` — `ts.to_zoned(tz).strftime("%Y-%m-%dT%H:%M:%S%.3f%:z")`, i.e. RFC 3339 with millis + offset (`2026-10-24T15:00:03.597+02:00`) instead of UTC `Z`; wired via `.with_timer(...)` at subscriber init with `TimeZone::get("Europe/Paris").unwrap_or(TimeZone::UTC)` (fail-soft: a stripped tzdb degrades to UTC, never to a compile error; created once at startup).
- Note on jiff 0.2 APIs hit in this session: `Timestamp::from_string` no longer exists (use `"…".parse::<Timestamp>()`), `TimeZone::fixed(offset)` is infallible, and `strftime(..).to_string()` is already `String` (Display swallows errors; harmless here since the format is fixed and representable) — plus a `Writer` import from `tracing_subscriber::fmt::format::Writer`.
- Since the timestamps come from the subscriber, **everything** switches at once: `ovalbot`, `tower_http`, and the parser's `log::` messages bridged through `tracing-log`.
- Tests (bin suite 3): fixed-timestamp formatting — winter `+01:00` (CET), summer `+02:00` (CEST), UTC fallback via `TimeZone::fixed(Offset::UTC)` — all asserting exact strings.
- README: one sentence under Backend ("Log timestamps are rendered in Paris time…").
